# Data

## WISDM activity-recognition data

Accelerometer data from the
[WISDM Smartphone and Smartwatch Activity and Biometrics Dataset](https://archive.ics.uci.edu/dataset/507/wisdm+smartphone+and+smartwatch+activity+and+biometrics+dataset)
(phone, 20 Hz). All variants share the same columns:
`subject_id, timestamp, x, y, z, label`.

The checked-in file is **`wisdm_subset.csv`** (~2 MB). A larger version can be
generated locally if needed.

| File | Subjects | Rows | Size | Version controlled |
|------|----------|------|------|--------------------|
| **`wisdm_subset.csv`** | 2 (1600, 1601) | 33,600 | ~2 MB | yes |
| `wisdm_labeled_stream.csv` | 15 (1600–1615) | 394,313 | ~23 MB | no |

Both files cover the same 6 activities (walking, jogging, stairs, sitting,
standing, clapping) and are generated by
[`make_wisdm_labeled_stream.py`](./make_wisdm_labeled_stream.py).

### Generating the data

```bash
# Checked-in subset: 2 subjects, 140s per activity → ~2 MB
uv run python data/make_wisdm_labeled_stream.py \
  --n-subjects 2 --seconds-per-activity 140 --out data/wisdm_subset.csv

# Optional larger file (not version controlled): 15 subjects, full duration → ~23 MB
uv run python data/make_wisdm_labeled_stream.py
```

The `--seconds-per-activity` flag trims each activity to a contiguous block of
that many seconds per subject. Without it, full segments (~3 min each) are kept.

The script reuses helpers from
[`make_demo_labeled_stream_wisdm.py`](./make_demo_labeled_stream_wisdm.py).
The raw WISDM data must already be extracted at `data/raw/wisdm/` (see the demo
script's `--dataset-zip` / `--dataset-dir` flags to download it).

## `synthetic_signals.csv` — known-answer signals

A synthetic table for checking non-forecasting tools against known answers:
3,000 samples at 50 Hz (60 s). `t` is time in seconds; each value column has a
documented ground truth.

| Column | Ground truth |
|--------|--------------|
| `periodic` | 2 Hz sine plus Gaussian noise (sd 0.3): period 0.5 s = 25 samples |
| `regime` | White noise whose mean shifts by +2 at sample 1000 (t = 20 s) and whose standard deviation triples at sample 2000 (t = 40 s) |
| `anomaly` | 0.5 Hz sine (period 100 samples) plus noise (sd 0.1), replaced by a flat line for samples 1500-1529 |

| File | Rows | Size | Version controlled |
|------|------|------|--------------------|
| **`synthetic_signals.csv`** | 3,000 | ~90 KB | yes |

Regenerate it (default `--seed 7` reproduces the checked-in file):

```bash
uv run python data/make_synthetic_signals.py --out data/synthetic_signals.csv
```

Example checks:

```bash
ts-agents tool run detect_periodicity --input data/synthetic_signals.csv \
  --time-col t --value-col periodic --json
ts-agents tool run segment_changepoint --input data/synthetic_signals.csv \
  --value-col regime --json
ts-agents tool run find_discords --input data/synthetic_signals.csv \
  --value-col anomaly --param m=100 --json
```

`detect_periodicity` takes `sample_rate` (50 Hz) from the regular `t` column
and reports a period of about 0.5 s. `segment_changepoint` places change-points
near samples 1000 and 2000; by default they are resolved to a coarse `jump`
grid, reported as a warning with `quality_status: review` (`--param jump=1`
gives full resolution). The top `find_discords` result overlaps samples
1500-1529, with a `robust_z` far above the other discords.

## `short_real.csv` — MHD shearing-box simulation

A small time-series dataset from a magnetohydrodynamic (MHD) simulation of the
shearing-box induction equation, computed with the
[SNOOPY](https://ipag.osug.fr/~lesurg/snoopy.html) pseudo-spectral code.

Each row records the time evolution of selected Fourier modes of the magnetic
field. The two value columns in the checked-in file are:

| Column | Physical quantity |
|--------|-------------------|
| `bx001_real` | Re(B_x(0,0,1)) — real part of the (0,0,1) Fourier mode of B_x |
| `by001_real` | Re(B_y(0,0,1)) — real part of the (0,0,1) Fourier mode of B_y |

`unique_id` encodes the run parameters: e.g. `Re200Rm200` means Reynolds number
Re = 200 and magnetic Reynolds number Rm = 200. `ds` is the (integer) time step.

| File | Runs | Rows | Size | Version controlled |
|------|------|------|------|--------------------|
| **`short_real.csv`** | 2 (Re200Rm200, Re175Rm175) | 10 | <1 KB | yes |

This file is a tiny smoke fixture: 5 rows per run. It is read by the
`--run-id/--variable` workflow options and the `get_series` tool, for example
`ts-agents workflow run forecast-series --run-id Re200Rm200 --variable bx001_real --horizon 1 --methods seasonal_naive`
or `ts-agents tool run get_series --param run_id=Re200Rm200 --param variable=bx001_real --json`.
Five points are too short for the periodicity test (`inspect-series` reports
`degraded` with `periodicity_not_assessed`) and say nothing about method
quality. For tool examples, pass a longer file with
`--input <file> --value-col <col>`, such as `synthetic_signals.csv`.

## `m4_monthly_mini.csv` — M4 Monthly workflow subset

A vendored mini-panel from the
[M4 Monthly dataset](https://github.com/Nixtla/datasetsforecast), intended for
the "professional forecasting workflow" spec and future smoke tests.

| File | Series | Rows | Horizon | Version controlled |
|------|--------|------|---------|--------------------|
| **`m4_monthly_mini.csv`** | 5 (`M4`, `M10`, `M100`, `M1000`, `M1002`) | 1,466 | 18-step monthly holdout per series | yes |

Schema:

- `unique_id`: M4 Monthly series identifier
- `split`: `train` or `holdout`
- `ds`: 1-based time index within the full series
- `y`: observed value

This subset is intentionally small enough for deterministic tests. It is useful
for workflow validation, but it is **not** meant to stand in for the full M4
benchmark.

### Exporting it as a forecast-panel input

`ts-agents data export-panel` writes the mini-panel as a CSV with exactly
`unique_id`, `ds`, `y` at month-start (`MS`) frequency:

```bash
ts-agents data export-panel m4-monthly-mini --split train --out panel.csv --json
ts-agents data export-panel m4-monthly-mini --split holdout --out holdout.csv
ts-agents workflow run forecast-panel --input panel.csv --freq MS \
  --horizon 18 --season-length 12 --methods seasonal_naive
```

`--split` is `train` (default), `holdout` or `all`. The source stores integer
time indexes, so the dates are a **synthetic alignment**: every series' last
train observation is placed at `--train-end` (default `2015-06-01`, which must
be a month start) and the holdout covers the next 18 months. They are not the
original M4 calendar dates. Keep the holdout out of `forecast-panel` input and
use it only to score the saved `forecast.csv`.

## `demo_labeled_stream.csv`

A small single-subject demo stream used for quick workflow demos and
window-size selection tutorials. This is the default path used throughout the
quickstart and workflow docs, and the documented default is the synthetic
generator:

```bash
uv run python data/make_synthetic_labeled_stream.py \
  --scenario gait --seconds 40 --seed 1337 \
  --out data/demo_labeled_stream.csv

uv run ts-agents workflow run activity-recognition \
  --input data/demo_labeled_stream.csv \
  --label-col label \
  --value-cols x,y,z \
  --output-dir outputs/activity
```

If you specifically want a phone-recorded WISDM demo stream instead, use
[`make_demo_labeled_stream_wisdm.py`](./make_demo_labeled_stream_wisdm.py).
